Shop API (1.0.0)

Download OpenAPI specification:

API Team: api@shop.example

Назначение

REST API интернет-магазина: управление каталогами, категориями, товарами и заказами. Позволяет фронтенду и внешним интеграциям работать с полным жизненным циклом заказа.

Ошибки

Все ошибки возвращаются в формате application/problem+json (RFC 9457).

Код Тип (type) Когда
400 .../bad-request некорректный запрос (битый JSON, невалидный UUID в пути)
401 .../unauthorized отсутствует или просрочен токен
403 .../forbidden нет нужного scope
404 .../not-found ресурс не найден
409 .../conflict конфликт уникальности/состояния (дубликат sku, повтор Idempotency-Key с другим телом)
422 .../unprocessable-entity нарушение бизнес-правила
429 .../too-many-requests превышен лимит запросов
500 .../internal-server-error непредвиденная ошибка сервера

Версионирование

Используется URI-версионирование (/v1). Аддитивные изменения (новые поля, новые эндпоинты) не меняют версию. Ломающие изменения выпускаются как /v2; старая версия поддерживается не менее 6 месяцев с заголовками Deprecation: true и Sunset: <RFC 1123 date>.

Идемпотентность

POST /v1/orders принимает заголовок Idempotency-Key (UUID). Повторный запрос с тем же ключом и тем же телом в течение 24 часов возвращает сохранённый результат первого запроса (код 201). Тот же ключ с другим телом — 409. Без ключа запрос выполняется, но без гарантии идемпотентности.

Rate limiting

Лимит — 100 запросов в минуту на токен. При превышении — 429 с заголовком Retry-After (секунды) и заголовками X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset.

Создать заказ

Требует scope orders:write. Каждый item.product_id должен существовать, быть status active и иметь stock > 0, иначе 422. unit_price и total_amount считаются сервером. Поддерживает Idempotency-Key: повтор с тем же ключом и телом за 24ч возвращает тот же заказ (201); тот же ключ, другое тело — 409.

string <uuid>
